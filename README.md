# realtime-buncombe

A daily, automated landslide-risk pipeline for Buncombe County, NC. Every day it
downloads the latest PRISM rainfall data, runs three prediction models, writes an
updated map layer, and pushes the results to GitHub — which triggers the public
website to redeploy on Render.

---

## How the system works (the big picture)

There are three moving parts, and only one of them runs on your computer:

1. **Your Mac (the worker).** A scheduled job (cron) runs a script once a day. The
   script downloads rainfall, runs the models, and `git push`es the new results.
2. **GitHub (the hub).** Holds the code and the lightweight web output. It does
   *not* need the large data files (see "What is and isn't in GitHub" below).
3. **Render (the website).** Watches the GitHub repo. Whenever a commit lands on
   `main`, Render automatically redeploys the site.

So the flow each day is:

```
cron (5 AM) ─▶ auto_update_once_daily.py ─▶ auto_update.py
                                              ├─ download_prism_daily.py   (gets rainfall)
                                              ├─ predict_daily_triple.py   (runs models)
                                              └─ git add / commit / push   (origin main)
                                                          │
                                                          ▼
                                                   GitHub (main)
                                                          │
                                                          ▼
                                                Render redeploys site
```

**Important:** Render is tied to GitHub, not to your computer. The website keeps
working as long as the daily `git push` keeps happening. Migrating to a new
computer just means making that daily push work again from the new machine.

## The scripts

- **`app/auto_update_once_daily.py`** — the entry point cron calls. It checks
  `logs/last_run.txt` so the pipeline runs at most once per day, then calls
  `auto_update.py` using the project's own venv Python.
- **`app/auto_update.py`** — the orchestrator. Waits for internet, runs the
  downloader, runs the predictor, then commits and pushes. Honors three optional
  environment variables: `RB_PYTHON`, `RB_GIT_REMOTE` (default `origin`),
  `RB_GIT_BRANCH` (default `main`).
- **`app/download_prism_daily.py`** — downloads PRISM daily precipitation for the
  last 30 days into `data/rain/`, extracts the `.tif`, and prunes old files.
  Driven by the `prism_sync:` block in `config.yaml`.
- **`app/predict_daily_triple.py`** — runs the logistic / random-forest / XGBoost
  models (`models/*.joblib`) over the static terrain grid + rainfall and writes the
  prediction outputs (e.g. `predictions/latest.geojson`).
- **`config.yaml`** — all paths, model definitions, and the PRISM download settings.
  Paths are resolved relative to the project, so they stay correct after a move.

### Portable paths
The scripts locate the project root by walking up to the `.project-root` marker
file at the top of the repo, so the project runs from **any folder on any Mac** —
do not delete `.project-root`.

## What is and isn't in GitHub

`.gitignore` excludes only:

- `data/rain/` — re-downloaded automatically every day, so it never needs to travel.
- `*.tif` — raster files; regenerated by the daily run.

Large files that exceed GitHub's limits are **not** kept on GitHub. That is fine:
GitHub only needs to feed Render the light web output. The complete project
(including any heavy model/grid files) is moved between computers using an
**external SSD**, not GitHub.

The repo also uses **Git LFS** and a custom SSH remote:

```
origin = git@github.com-buncombe:WonjunChoi1004/realtime-buncombe.git
```

The `github.com-buncombe` part is an SSH host alias defined in `~/.ssh/config`,
which points at a specific SSH key. That config and key live in `~/.ssh/` — **not**
in this repo — so they must be copied to any new machine (see below).

## Setting it up on a new Mac

### 1. Copy the project from the SSD
Copy the entire `realtime-buncombe` folder (including the hidden `.git` folder)
from the external SSD to `~/PycharmProjects/realtime-buncombe`. Use the SSD, not
GitHub — the SSD has the heavy files GitHub doesn't.

### 2. Install prerequisites
```bash
brew install git git-lfs python
git lfs install
```

### 3. Rebuild the Python environment
The old `venv/` does not transfer (it has machine-specific paths). Recreate it:
```bash
cd ~/PycharmProjects/realtime-buncombe
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
deactivate
```

### 4. Restore Git/SSH access
Copy `~/.ssh/` from the old Mac (the private key **and** the `~/.ssh/config` block
that defines `Host github.com-buncombe`). Then verify:
```bash
ssh -T git@github.com-buncombe
```
You should see a GitHub success message. If GitHub reports the account is
restricted, that must be resolved first (see Troubleshooting).

### 5. Reinstall the daily schedule
Run `crontab -e` and paste:
```cron
SHELL=/bin/bash
PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

0 5 * * * cd "$HOME/PycharmProjects/realtime-buncombe" && "$HOME/PycharmProjects/realtime-buncombe/venv/bin/python" app/auto_update_once_daily.py >> "$HOME/PycharmProjects/realtime-buncombe/logs/cron.log" 2>&1

@reboot cd "$HOME/PycharmProjects/realtime-buncombe" && "$HOME/PycharmProjects/realtime-buncombe/venv/bin/python" app/auto_update_once_daily.py >> "$HOME/PycharmProjects/realtime-buncombe/logs/cron.log" 2>&1
```
The 5 AM line is the daily run; the `@reboot` line is a catch-up if the Mac was off
overnight.

### 6. Grant cron permission (macOS requirement)
System Settings → Privacy & Security → Full Disk Access → add `/usr/sbin/cron`.
Without this, the scheduled job fails silently.

### 7. Test it once manually
```bash
cd ~/PycharmProjects/realtime-buncombe
venv/bin/python app/auto_update_once_daily.py
tail -n 40 logs/cron.log
```
A successful run downloads rainfall, writes predictions, and pushes a commit. Check
GitHub for a new `Auto-update:` commit and confirm Render redeploys.

## Troubleshooting

- **`git push` fails / "Access to this site has been restricted."** The GitHub
  account is flagged. No machine can push until it's lifted — log in at github.com
  and follow the appeal/verification prompt, or contact support.github.com. The
  local pipeline still runs and commits; only the push (and therefore the website
  update) is blocked.
- **Job never runs at 5 AM.** The Mac must be awake at 5 AM. Either keep it awake
  (e.g. a `pmset` wake schedule) or rely on the `@reboot` line. Also confirm Full
  Disk Access (step 6).
- **`venv/bin/python: No such file`.** The venv wasn't rebuilt — redo step 3.
- **SSH push asks for a password or fails auth.** `~/.ssh/config` /key wasn't
  restored — redo step 4 and re-test with `ssh -T git@github.com-buncombe`.

## Optional: remove the laptop dependency

Because the only role of the computer is to run one daily script and push, the
whole job can be moved to a free **GitHub Actions scheduled workflow** (cloud cron).
It would download, predict, commit, and push on GitHub's servers daily — no laptop,
no local cron, no "is the Mac awake" problem. (The GitHub account restriction would
still need to be resolved first.)
